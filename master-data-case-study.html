Catching master data problems before go-live, not after

Concept case study · 2026 · Based on my master data preparation work on a DMS rollout

The context

A DMS is only as good as its master data: distributors, shops, products, salesmen, geographies and price lists. On my last rollout I prepared and reconciled master data for two markets before deployment.

Most of that work is checking for the same kinds of problems again and again. This concept automates those checks, so people deal only with the rows that need fixing.

The problem

Data problems are found late, when they are most expensive to fix:

  • Master data arrives in different spreadsheet formats.
  • Thousands of rows are checked by eye.
  • Duplicates, missing tax IDs and wrong mappings show up in testing or after go-live.
  • Every reload means retesting.

What I did

  • Listed the checks I ran by hand while preparing master data for my rollout.
  • Designed standard templates and automated readiness checks.
  • Defined which problems block a load and which only raise a warning.
  • Wrote the check rules as a sample for a build team.

The approach

  1. 1
    One template per data typeFixed columns, required fields and allowed values for each data type.
  2. 2
    Check every file automaticallyReadiness checks run on every upload and list every problem found.
  3. 3
    Send back only what's wrongFlagged rows go back to the distributor with the reason, so they fix just those rows.
  4. 4
    Separate blockers from warningsA missing tax ID blocks a load. A missing phone number only raises a warning.
  5. 5
    Approve, then loadThe data team approves each file before it is loaded into the DMS.

Expected outcomes

  • Fewer data defects in UAT and after go-live.
  • Distributors fix only what's wrong, not whole files.
  • Faster, more predictable data loads before each go-live.
  • A reusable checklist for the next market.

Design principles

  • Agree the template before collecting any data.
  • Separate blockers from warnings, or everything becomes urgent.
  • Master data needs a business owner, not just an IT one.
